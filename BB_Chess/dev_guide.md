## **1\. 프로젝트 개요 및 시스템 아키텍처**

롤토체스(TFT)의 상점 리롤, 기물 3성 합성, 시너지 조합, 이자 경제 시스템을 30종의 말랑쁘니 캐릭터에 맞춰 경량화한 싱글플레이 오토배틀러 웹 애플리케이션입니다.

> * **개발 목표:** 별도의 백엔드 서버나 Node.js 번들링 과정 없이 브라우저에서 즉시 구동되는 100% 정적 웹페이지(Zero-Build Static Web)로 상용 수준의 오토배틀러 게임성을 구현합니다.  
> * **타겟 디바이스 및 해상도:** 스마트폰 세로 화면(논리 해상도 390x844 픽셀, 9:16 고정 종횡비)을 기준으로 설계하며, PC 브라우저 접속 시 화면 중앙에 모바일 베젤 프레임으로 렌더링합니다.  
> * **아키텍처 비평 및 설계 원칙:** 정지된 2D 피규어 이미지의 시각적 한계를 극복하기 위해 논리 틱(100ms)과 렌더링 프레임(16.6ms, 60FPS)을 분리하고, 포물선 점프 보간과 타격 시 젤리 탄성 변형(Squash & Stretch)을 코드로 연산합니다.

| 계층 구분 | 채택 기술 | 담당 역할 | 데이터 처리 | 비고 |

## **2\. 기능 요구사항 명세 (FRS)**

### **2.1. 전장 그리드 및 대기석 공간 제어 (FR-01)**

> * **전장 규격:** 중앙 Canvas 영역을 5열 6행(총 30타일, 단일 타일 68x68 픽셀)으로 분할하여 상단 3행(Row 0\~2)은 적군 배치 구역, 하단 3행(Row 3\~5)은 아군 배치 구역으로 할당합니다.  
> * **대기석(Bench) 규격:** 전장 하단에 1열 7칸(Slot 0\~6)의 대기석을 배치하며, 상점에서 구매한 기물은 빈 대기석 좌측부터 순차 생성됩니다.  
> * **배치 제한 및 스왑:** 플레이어 레벨(3\~9레벨)에 따라 전장에 배치 가능한 최대 아군 기물 수를 3\~9개로 제한하며, 이미 기물이 있는 타일로 드래그 앤 드롭할 경우 두 기물의 위치를 즉시 맞바꿉니다.

### **2.2. 공유 기물 풀 및 3성 자동 합성 시스템 (FR-02)**

> * **기물 공유 풀(Shared Pool):** 코스트별 전체 기물 수량(1코스트 18장, 2코스트 15장, 3코스트 12장, 4코스트 10장, 5코스트 8장)을 배열로 관리하며, 상점 노출 및 구매 시 풀에서 차감하고 판매 시 풀로 반환합니다.  
> * **3성 자동 합성:** 대기석과 전장을 합산하여 동일한 ID와 성급(Star)을 가진 기물이 3개 모이는 즉시 1개 상위 성급(1성→2성→3성) 기물로 통합하고, 체력과 공격력을 성급당 1.8배씩 증폭합니다.

### **2.3. 골드 경제 및 라운드 진행 루프 (FR-03)**

> * **수입 정산:** 매 라운드 종료 시 기본 보수 5골드, 보유 골드 10단위당 이자 \+1골드(최대 \+5골드), 연승 또는 연패 보너스(2연속 \+1, 4연속 \+2, 5연속 이상 \+3골드)를 합산하여 지급합니다.  
> * **비용 지출:** 상점 리롤에 2골드, 경험치 구매(4 XP 증가)에 4골드가 소모되며, 기물 판매 시 1성은 원가 전액, 2\~3성은 합성 원가에서 1골드를 차감한 금액을 환급합니다.  
> * **라운드 구성:** 총 15스테이지로 구성하되 각 스테이지는 준비 페이즈(시간 제한 없음, 전투 시작 버튼 수동 클릭)와 전투 페이즈(최대 30초, 초과 시 시간 가속 버프 발동)로 순환합니다.

### **2.4. 틱 기반 전투 상태 머신 및 길찾기 (FR-04)**

> * **타겟팅 규칙:** 모든 기물은 매 틱(100ms)마다 체비쇼프 거리(max(∣*r*1​−*r*2​∣,∣*c*1​−*c*2​∣)) 기준으로 가장 가까운 생존 적군을 탐색하여 타겟으로 지정합니다.  
> * **이동 및 타일 예약:** 타겟이 사거리 밖에 있을 경우 인접 8방향 빈 타일 중 타겟과 가장 가까워지는 타일을 선점(Reservation)하여 이동하며, 두 기물이 동일 타일로 겹치는 현상을 방지합니다.  
> * **마나 및 스킬 발동:** 평타 공격 시 마나 10 회복, 피격 시 5 회복을 기본으로 하며, 마나가 최대치(100)에 도달하면 다음 틱에 고유 궁극기를 시전하고 마나를 0으로 초기화합니다.

### **2.5. 5장 단체 사진 오프스크린 자동 크롭 로더 (FR-05)**

> * **이미지 분할 파이프라인:** 사용자가 6종씩 나열된 피규어 단체 사진 5장을 업로드하면, 오프스크린 Canvas가 각 이미지를 가로 6등분(단일 영역 너비 *W*/6, 높이 *H*)으로 잘라 256x256 정사각형 스프라이트 30개를 추출합니다.  
> * **영구 캐싱 및 폴백:** 추출된 30개의 이미지 DataURL을 브라우저 IndexedDB에 저장하여 재접속 시 자동 로드하며, 사진 업로드 전에는 각 캐릭터의 대표 색상과 특징 아이콘이 그려진 프로시저럴 아바타로 렌더링합니다.

## **5\. 전투 수학 공식 및 핵심 데이터 스키마**

안티그래비티 에이전트가 전투 연산과 상태 관리를 일관되게 구현하기 위한 수학 공식과 표준 데이터 스키마입니다.

> * **방어력 감쇄 공식:** 최종 피해량은 Damage=RawAtk×100+Defense100​ 공식을 적용하여 방어력이 높아져도 피해량이 0이 되지 않고 점근적으로 감소하도록 처리합니다.  
> * **성급(Star) 스케일링 공식:** 성급 $S\in 1,2,3$에 따른 스탯 배율은 $M(S)=1.{8}^{S-1}$을 적용하여 1성 1.0×, 2성 1.8×, 3성 3.24×로 자동 계산합니다.

// 전역 게임 상태 스키마 (AppState)  
export const AppState \= {  
  stage: 1,  
  phase: 'PREP',          // 'PREP' \| 'COMBAT' \| 'SETTLE'  
  playerHp: 100,  
  gold: 10,  
  level: 3,  
  xp: 0,  
  streak: 0,              // 양수: 연승, 음수: 연패  
  shopLocked: false,  
  shopSlots: \[null, null, null, null, null\],  
  bench: new Array(7).fill(null),  
  board: Array.from({ length: 6 }, () \=\> new Array(5).fill(null)),  
  activeSynergies: {},  
  spriteCache: {}         // P01 \~ P30 크롭 이미지 Image 객체  
};

// 전투 기물 엔티티 구조체 (CombatUnit)  
export class CombatUnit {  
  constructor(spec, star, isEnemy, row, col) {  
    this.uid \= crypto.randomUUID();  
    this.id \= spec.id;  
    this.name \= spec.name;  
    this.star \= star;  
    this.isEnemy \= isEnemy;  
    this.row \= row;  
    this.col \= col;  
    this.x \= 0;  
    this.y \= 0;  
    const mult \= Math.pow(1.8, star \- 1);  
    this.maxHp \= Math.round(spec.hp \* mult);  
    this.hp \= this.maxHp;  
    this.atk \= Math.round(spec.atk \* mult);  
    this.def \= spec.cost \* 10;  
    this.range \= spec.range;  
    this.mp \= 0;  
    this.maxMp \= 100;  
    this.atkSpeed \= 1.0;  
    this. chillTimer \= 0; // 오싹쁘니·원소판타지 빙결 상태이상  
    this.stunTimer \= 0;   // 단단쁘니·뚝딱쁘니 기절 상태이상  
  }  
}

## **6\. 안티그래비티 IDE 단계별 바이브 코딩 지시 프롬프트**
